# Безопасность

Документ описывает, что сервис защищает сам, что остаётся ответственностью
оператора и какие проверки выполняются в репозитории. Публикация исходного кода
не открывает дополнительных HTTP-endpoint'ов: набор маршрутов задан кодом и
ограничен теми же лимитами, что и раньше.

## Приватность по умолчанию

* Сервис не создаёт учётных записей и не хранит пользовательские данные: в базе
  лежат только каталог, журнал попыток обращения к внешним API и квоты
  помощника.
* Uvicorn запускается без access-log (`run.py`: `access_log=False`), поэтому URL
  и координаты не попадают в логи; фильтр `SafeServerErrors` заменяет traceback
  ASGI-сервера на тип ошибки, а предформатированный traceback времени жизни — на
  понятное сообщение без внутренних путей.
* Ошибки валидации возвращаются обезличенно («Некорректное значение
  параметра.»), ошибки базы — как `503` без деталей SQL и путей файловой
  системы; `hide_input_in_errors` не даёт секретам попасть в текст ошибок
  настроек.
* Внешним службам не передаётся геометрия пользователя: запросы погоды и
  пыльцы уходят с фиксированного центроида, поэтому поставщик не узнаёт, где
  человек идёт.

## Ограничение входа

`RequestLimitsMiddleware` работает до маршрутизации:

| Ограничение | Параметр |
| --- | --- |
| Размер тела запроса | `REQUEST_MAX_BYTES` (по умолчанию 16 КиБ), `413` при превышении |
| Таймаут чтения тела | `REQUEST_BODY_TIMEOUT_SECONDS`, `408` |
| Размер строки параметров | `QUERY_MAX_BYTES`, `414` |
| Анонимный лимит поисковых запросов | `SEARCH_CLIENT_RATE_LIMIT` за `SEARCH_CLIENT_WINDOW_SECONDS`, `429` с `Retry-After` |
| Число отслеживаемых адресов | `SEARCH_CLIENT_MAX_ENTRIES`: при переполнении новые адреса отклоняются, активные лимиты не вытесняются |
| Конкурентность соединений | `SERVER_CONCURRENCY_LIMIT` (uvicorn) |

Лимит поисковых запросов — внутрипроцессный: он защищает от всплесков, но не
является распределённым счётчиком и сбрасывается при перезапуске. Долговременную
защиту бюджета даёт журнал ниже.

## Бюджет внешних вызовов и квоты помощника

* Перед каждым обращением к Яндексу попытка **сначала** записывается в
  таблицу `upstream_quota_ledger` внутри `BEGIN IMMEDIATE`: чтение, запись,
  блокировка или commit — любая ошибка означает, что внешнего вызова не будет
  (`503` вместо тихого обхода защиты).
* Ограничения: серверный лимит за окно и суточный бюджет (`YANDEX_*_DAILY_BUDGET`)
  в скользящих 24 часах, а не «по календарю поставщика». Неудачные и
  отменённые попытки не возвращаются в бюджет.
* Параллелизм ограничен счётчиком допуска на процесс (`YANDEX_MAX_CONCURRENT`), без
  очереди: при перегрузке возвращается `503` с `Retry-After`.
* Помощник ведёт durable-квоты на источник и глобально (минута/сутки), плюс
  дешёвый внутрипроцессный предлимит, ограничивает одновременные обращения к
  модели, длину сообщения, истории и ответа, и запрещает платный роутинг
  (`AI_ASSISTANT_FREE_ONLY` нельзя отключить).

## Ключи и секреты

* Ключи Яндекса, OpenRouter и операторские хэши живут только на сервере; клиент
  не получает их ни в ответах, ни в ошибках, ни в SSE-событиях.
* Хэши доступа и соль источников принимаются только как lowercase SHA-256 —
  сам секрет в конфигурации не хранится.
* `.env` и любые реальные конфигурации исключены из репозитория (`*.env`,
  `.env.*`, `*.key`, `*.pem`, `*.jks`, `*.keystore`, базы и логи — в
  `.gitignore`), но `.gitignore` **не** считается защитой: перед публикацией по
  worktree, индексу и всей истории прогоняется собственный сканер
  `tools/scan_credentials.py` (подписи известных токенов, приватные ключи,
  URL-учётные данные, высокоэнтропийные литералы, структурные значения с
  «секретными» именами). Исключения сканера возможны только для точной пары
  «путь + правило + SHA-256 значения» с обоснованием и не распространяются на
  подписи и приватные ключи (`tools/credential_scan_allowlist.json`).
* Клиентский ключ Yandex MapKit относится к мобильному приложению и в этом
  репозитории не публикуется: в публичной сборке он безопасно передаётся процессу сборки, а его защита опирается на ограничения ключа у поставщика, а
  не на сокрытие.

## Контейнер

Нерутовый пользователь 10001, read-only корневая файловая система, `tmpfs` для
`/tmp` без права выполнения, `cap_drop: ALL`, `no-new-privileges`, файлы
приложения доступны только на чтение, а в образ попадают лишь приложение и три
ODbL-датасета по allowlist. Права тома `volatile`: bootstrap меняет владельца
только самого каталога `/data` и только когда платформа явно сообщает о таком
монтировании; иначе старт отклоняется (см. [DEPLOYMENT.md](DEPLOYMENT.md)).

## Модель угроз и границы

| Угроза | Что сделано |
| --- | --- |
| Утечка ключей через API | ключи только на сервере; ответы и SSE не содержат секретов; сканер секретов в CI |
| Исчерпание бюджета внешнего API | durable-журнал попыток, суточные бюджеты, серверный rate limit, семафор |
| Раздутые запросы, медленный клиент | лимиты размера и таймауты до маршрутизации |
| Подмена хоста внешнего API | домен и путь Яндекса/OpenRouter закреплены валидаторами |
| Подмена адреса клиента | доверенные прокси задаются явно (`TRUSTED_PROXY_IPS`), `0.0.0.0/0` запрещён; для лимита поиска заголовки пересылки разбирает ASGI-сервер, а не приложение; квоты помощника считают доверенные хопы `X-Forwarded-For` по `AI_ASSISTANT_TRUSTED_PROXY_HOPS` |
| Утечки через логи | access-log выключен, traceback и текст запроса вырезаны фильтром |
| Подделка данных | датасеты только на чтение, целостность Quiet проверяется SHA-256-манифестом, происхождение проверяется `tools/verify_extraction.py` |

Осознанно **вне** возможностей сервиса: защита от распределённого отказа в
обслуживании, WAF и TLS (задача оператора), а также внутрипроцессные лимиты
частоты после перезапуска. Сканер секретов — эвристика и не даёт гарантии
«секретов нет вообще», поэтому отчёт сканера дополняет ручной обзор, а не
заменяет его.

## Что делать при находке

Сообщите автору приватно (issue в репозитории без публикации эксплойта или
письмо автору). Указывайте минимальный воспроизводимый пример и версию ревизии;
не прикладывайте действующие ключи и персональные данные. Пожалуйста, дайте
время на исправление до публичного раскрытия.
