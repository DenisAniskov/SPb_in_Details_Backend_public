# Phase C7.3 — Модель пыльцевой нагрузки (v1)

`method = "experimental_pollen_exposure"`, `method_version = "c7_3.1"`.

Документ описывает ровно то, что считает движок, в каких единицах, и — не
менее важно — что он **не** считает и почему.

## 1. Семантика времени: `[t, t+1h)`, а не `(t−1h, t]`

Это главное отличие C7.3 от C7.2, и его нельзя «переиспользовать».
Open-Meteo отдаёт для воздуха **мгновенные** значения: «most weather variables
are given as an instantaneous value for the indicated hour». Значит значение с
меткой `t` действительно для часа **`[t, t+1h)`** — часа ВПЕРЁД от метки.

В C7.2 осадки, наоборот, описаны как сумма за предыдущий час `(t−1h, t]`.
Если бы движок пыльцы унаследовал логику осадков, прогулка, начинающаяся
ровно в `t`, получила бы **ноль** вместо значения часа, в котором она идёт, —
то есть систематическую ошибку ровно в тот час, который пользователь
проходит. Поэтому:

* временная семантика реализована отдельно (`source.py`, `model.py`);
* тест `test_instantaneous_bins_are_not_precipitation_bins` фиксирует: бины
  `t−1h → 4.0`, `t → 7.0`, `t+1h → 9.0` дают для прогулок, начинающихся в
  `t−1h`, `t` и `t+1h`, ровно 4.0, 7.0 и 9.0;
* ни одна функция накопления осадков (`_bin_inputs`, «уже выпавшая доля»,
  затухание по возрасту) в пыльце не используется: у мгновенной
  концентрации нет «выпавшей доли» и нет высыхания.

## 2. Время прохождения: доля длины × native-длительность

Как в C7.1/C7.2, чтобы расчёт не зависел от плотности вершин MapKit:

* участок `leg` занимает **ровно** `[clock, clock + walking_duration_seconds]`;
* `clock` наращивается на `walking_duration + visit_duration_after_leg`, то
  есть **осмотр POI сдвигает все последующие этапы**;
* внутри этапа время пропорционально длине (native-секунды распределены по
  длине), поэтому «доля длины» и «доля времени» — одно и то же, и длины
  метров считаются по этой же пропорции.

**Под-нарезки 40 м здесь нет — сознательно.** В C7.2 40-метровые куски нужны,
потому что покрытие OSM меняется вдоль линии. У пыльцы нет ни одного
пространственного различия внутри ячейки, а временное разрешение источника —
один час: нарезка меньше этапа изображала бы разрешение, которого у данных
нет. Этап, пересекающий границу часа, при этом считается **точно** — интеграл
складывается из перекрытий с бинами, а не «округляется» к одному часу.

## 3. Что складывается в числа

Для вида `s` и множества окон ходьбы `W`:

```
overlap(bin, window)   = секунды перекрытия часа [t, t+1h) с окном
known_seconds_s        = Σ overlap по бинам, где значение вида НЕ null
exposure_s  [grains·h/m³] = Σ c_s(bin)[grains/m³] × overlap / 3600
mean_s      [grains/m³]   = exposure_s / (known_seconds_s / 3600)
peak_s      [grains/m³]   = максимум c_s по известным бинам, пересекающим W
```

Свойства, которые из этого следуют и закреплены тестами:

* **единицы честные.** `exposure` — это произведение концентрации на время,
  `grains·h/m³`. Это **не** индивидуальная вдыхаемая доза (для дозы нужен
  объём вдоха, который мы не знаем и не спрашиваем) и **не** прогноз
  симптомов.
* **среднее не разбавляется неизвестностью.** `mean` делится на *известные*
  часы, а не на всю прогулку: два часа ходьбы, из которых известен один час
  со значением 10.0, дают среднее **10.0**, а не 5.0. Разбавление нулём
  скрыло бы загрязнение; поэтому рядом публикуется `known_share`.
* **интеграл покрывает только известную долю.** `exposure` не продлевается на
  неизвестное время: продлить ряд за горизонт прогноза — значит выдумать
  данные. Клиент получает `known_share` рядом с интегралом именно для этого.
* **время осмотра POI не накапливается.** О среде внутри музея, кафе или
  двора источник не говорит ничего, поэтому визит только сдвигает часы
  следующих этапов. Тест
  `test_a_poi_visit_shifts_later_legs_and_is_not_accumulated` фиксирует
  интеграл 6,5, а не 13,0, для прогулки «30 мин + час в POI + 30 мин».
* **инвариант согласованности**: `mean × known_hours == exposure` без
  округления (тест `test_the_mean_and_the_integral_stay_consistent_with_their_units`).

## 4. Покрытие: что такое «известно»

| Уровень | Определение |
|---|---|
| Час вида `s` | бин существует в ряду и `c_s != null` |
| Час «всей панели» | бин существует и **все запрошенные виды** непусты |
| Метры прогулки (`known_meters`) | доля длины этапа × доля времени его окна, где известна вся панель |
| `known_share` вида | известные секунды этого вида ÷ всё время ходьбы |
| `outside_source_cell` | этап, у которого **хотя бы одна вершина** вне ячейки источника |

Почему метры считаются по «всей панели»: карточка показывает виды вместе,
и час, где один вид отсутствует, не является полной картиной. Точный
покрытийный ответ по каждому виду при этом тоже публикуется отдельно
(`known_share`, `status` вида).

**Следствие: если полной панели нет ни на одном часе, чисел нет вообще**
(C7.3.1). Вердикт маршрута — `unavailable`, и по контракту на `unavailable`
не публикуется ни одно число, включая виды, известные на всей прогулке.
При этом `known_seconds`/`known_share` видов **не обнуляются**: это покрытие
источника, и оно остаётся правдой («значения были, числа удержаны»). Отсюда
два разных кода причин:

* `pollen_no_data` — у всех видов `known_share == 0`: источник не дал ничего;
* `pollen_no_complete_panel` — какие-то виды значения имели, но ни на одном
  часе не было всех шести сразу; `diagnostics.species_withheld` называет,
  сколько видов чьи числа не опубликованы.

Считать «частичные значения» полной картиной нельзя: 5 из 6 видов — это не
шесть, а ноль часов полной панели означает, что сравнивать эти числа между
собой или с чем-либо на уровне маршрута не с чем. Ровно поэтому
`pollen_incomplete` (часть прогулки без значений) и
`pollen_no_complete_panel` (нет ни одного часа с полным набором) — разные
сообщения, и ни одно из них не превращается в «чисто».

**Временная доля и долевая доля метров — разные числа, и это не ошибка.**
Этап в 600 м и этап в 125 м по 1800 с каждый дают временную долю 0,5 и
долевую `coverage_share` около 0,83. Ни одно из чисел не подгоняется под
другое; тест
`test_a_leg_outside_the_source_cell_is_unknown_not_borrowed` фиксирует обе
величины и то, что `coverage_share == known_meters / route_length_meters`.

## 5. Пространственная корректность

* Один запрос на один фиксированный центроид. Значение описывает **одну**
  ячейку CAMS ~11 км (`[59.85, 59.95) × [30.25, 30.35)` для центроида
  пилота).
* Этап вне этой ячейки остаётся `unknown` (`outside_source_cell`): брать
  значение соседней ячейки, которую мы не запрашивали, — выдумка.
* Внутри ячейки значение зависит **только от часа** прохождения. Тест
  `test_the_value_of_a_leg_depends_on_the_hour_only_not_on_where_it_is`
  фиксирует: два этапа в разных местах с одинаковым часом получают
  одинаковые значения.
* Вследствие этого **сравнение улиц не делается вообще**, а не «делается
  осторожно». ТЗ §8 требует не выдавать альтернативные улицы за «более
  безопасные», если значения источника пространственно одинаковы, — здесь
  они одинаковы по построению.
* Плотность вершин одной и той же линии на ответ не влияет
  (`test_vertex_density_of_the_same_polyline_changes_nothing`).

## 6. Чего в модели нет

| Не реализовано | Почему |
|---|---|
| Суммирование видов в «риск аллергии» | ТЗ §4: без обоснования складывать аллергены нельзя. Виды публикуются отдельно |
| Пороги «низко/умеренно/высоко» | Пороги требуют проверенного источника для каждого вида. Их нет — значит, нет и уровней |
| Медицинские категории, советы, «безопасно» | Не медицинский продукт; данные модельные |
| Доза, объём вдоха | Требует персональных данных, которых мы не собираем |
| Интерполяция между часами | Источник не даёт разрешения меньше часа; линейная интерполяция создала бы значения, которых модель не считала |
| Заполнение `null` нулём | Отсутствие данных ≠ ноль |
| Продление ряда за горизонт | Прогноза за горизонтом нет |
| Маршрутизация по пыльце | Отдельный этап (ТЗ §8), здесь не реализуется |
| Персонализация по видам пыльцы | Отдельный согласованный этап |

Коэффициентов у модели **нет вообще**: ни τ, ни насыщения, ни порогов.
Поэтому у C7.3 нет блока `sensitivity`, который был в C7.2 (там он показывал
зависимость ответа от экспериментальных параметров). Вместо него ответ
несёт список `assumptions` — те допущения, которые действительно были
сделаны, и модель требует их наличия там, где есть числа.

## 7. Коды причин

| Код | Смысл |
|---|---|
| `pollen_not_configured` | источник не включён оператором (поведение по умолчанию) |
| `pollen_unavailable` | сеть/таймаут/5xx |
| `pollen_source_invalid` | ответ не прошёл проверку контракта (§4 в SOURCE_FEASIBILITY) |
| `pollen_stale` | ряд получен слишком давно (> 90 мин) |
| `pollen_outside_window` | прогулка целиком вне интервала ряда |
| `pollen_no_data` | внутри интервала, но значений нет ни у одного вида (`known_share == 0` у всех) |
| `pollen_no_complete_panel` | значения у части видов есть, но ни на одном часе нет полной панели: числа удержаны (C7.3.1) |
| `outside_source_cell` | часть этапов вне ячейки источника |
| `pollen_incomplete` | часть прогулки без значений |
| `modeled_pollen_concentration` | числа основаны на модельном прогнозе |
| `experimental_uncalibrated` | версия экспериментальная, без калибровки |

## 8. Тексты ограничений, которые всегда возвращаются

1. Это концентрации в воздухе, а не индивидуальная вдыхаемая доза и не
   прогноз симптомов.
2. Данные — модельный прогноз CAMS, а не измерения: шаг 1 час, сетка 0,1°
   (~11 км) на всю агломерацию.
3. Модель не различает улицу, двор, парк и тротуар внутри одной ячейки.
4. Порогов опасности и медицинских категорий нет.
5. Виды не суммируются в «риск аллергии».
6. Часы за горизонтом прогноза остаются неизвестными.
7. Ноль — значение модели, а не подтверждённое отсутствие пыльцы; в
   межсезонье ноль ожидаем и не означает индивидуальной безопасности.
8. Время осмотра POI не входит в накопление.

Если часть прогулки неизвестна, добавляется девятое: такие метры не получают
чисел и **не считаются чистыми**.

## 9. Что было бы нужно для `MODEL_VALIDATED`

Не сделано и не заявлено: наземные измерения пыльцы для сравнения,
независимая проверка сезонных максимумов, калибровка концентраций,
согласованные с источником пороги для каждого вида, план приёмки на
устройстве. До этого момента корректная формулировка — «модельные
концентрации с честным покрытием», и ничего больше.
