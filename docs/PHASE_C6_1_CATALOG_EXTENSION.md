## Отбор и происхождение координат

- Каждое место привязано ровно к **одному каноническому объекту OSM**,
  полученному целевым ограниченным запросом Overpass 2026-10-11
  (`docs/phase_c6_1_acquisition/`; журнал `requests.json` хранит точный текст
  запроса, конечную точку, время, хеш SHA-256 и размер каждого ответа).
- Привязка к доказательству — **последний успешный ответ на финальный текст
  запроса**: если запрос уточнялся, все предыдущие попытки и ответы остаются в
  журнале как история (46 неуспешных попыток публичных шлюзов зафиксированы;
  суперседед-ответы сохранены отдельными файлами и не используются).
- `docs/phase_c6_1_osm_source_snapshot.json` содержит ровно 7 выбранных
  элементов — побайтно те же объекты, что и в ответах Overpass.
- Текущее состояние объектов дополнительно проверено через **официальный OSM
  API 0.6** (`current_node_0`, `current_way_0`, `current_relation_0`), с
  контролем хешей и даты: версии и теги совпадают со снимком, координаты узлов
  не изменились.
- Районы назначены воспроизведением замороженных полигонов Phase B/C2
  (`docs/phase_c6_1_district_assignments.json`); новые границы не приобретались
  (`docs/phase_c6_1_boundary_note.json`).
- Все 49 именованных кандидатов из семи запросов получили явное решение
  (`docs/phase_c6_1_candidate_review.json`): 7 приняты, 42 отклонены с
  указанием причины (например, второй узел «Арт-центра Пушкинская 10» —
  принят более полный канонический объект; «Елагин дворец» уже представлен
  записью `yelagin-palace-museum`).
- Пары ближе 120 м: ни одна пара с участием новых мест не попадает в порог;
  набор близких пар замороженного окна не изменился

### Классификация адресов

Введён один новый класс адресного происхождения —
`official_source_verified` (адрес сверен с официальным источником на дату
фазы; источник обязан быть указан в `verification_evidence`, иначе аудит
завершается ошибкой). Он используется пятью карточками; две карточки
(«Этажи», «Волшебная миля») имеют класс `osm_tags`, поскольку адрес
подтверждён тегами `addr:*` самого OSM-объекта. Валидатор Phase B принимает
новый класс аддитивно; замороженные манифесты B/C2/C3 при этом не меняются.

## Честность данных

- Координаты — **репрезентативные точки** (узел OSM или центр ограничивающего
  прямоугольника way/relation), а не подтверждённые входы:
  `access_point_status = representative_point_not_verified` у всех семи;
  routing-схема не заполнена (`routing_*` отсутствуют).
- Каждая карточка содержит предупреждение о непроверенном доступе
  («Доступ и пешеходный подход независимо не проверены…»); у парковой прогулки
  явно указано «прогулка по части парка».
- Часы работы, рейтинги, фотографии, стили и годы не выдумываются:
  `working_hours`, `rating`, `photo_url`, `architectural_style`, `year_built` —
  `null`; расписание отнесено к официальному сайту.
- Исторические имена/детали, не подтверждённые источником, в карточки не
  вносились; справка о здании бывшего хлебозавода для «Этажей» опирается на
  статью Википедии (вспомогательный источник) и помечена в
  `verification_evidence`.
- Приобретение опирается на данные OSM как источник географических фактов
  (ODbL); OSM не используется как подтверждение исторических дат или событий.

## Воспроизведение

Из каталога `backend`:

```
python -m scripts.acquire_phase_c6_1_osm            # сеть; норм. только при отсутствии локального кеша
python -m scripts.check_phase_c6_1_current_objects  # сеть; официальный OSM API 0.6
python -m scripts.build_phase_c6_1_catalog          # офлайн; собирает seed и артефакты
python -m scripts.validate_phase_c6_1_catalog       # офлайн; --write-reports обновляет манифест
python -m scripts.validate_phase_b_catalog          # замороженное окно Phase B
python -m scripts.validate_phase_c2_catalog         # замороженное окно C2
python -m scripts.validate_phase_c3_catalog         # замороженное окно C3 (173)
```
