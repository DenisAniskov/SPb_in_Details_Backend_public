# Phase C7.3 — Source feasibility gate (pollen)

Итог шлюза: **источник пригоден для инфраструктуры C7.3 и подтверждён
фактическими запросами, но пригодность подтверждена не для «точности
прогноза», а для контракта данных.** Прогноз пыльцы остаётся модельным
рядом с шагом сетки 0,1° (~11 км), и `MODEL_VALIDATED` по-прежнему **не
присвоен**: наземных измерений пыльцы для сравнения нет.

Дата проверки: **2026-10-16**, 18:29–18:38 UTC. Все запросы — один
фиксированный центроид центра Петербурга; геометрия пользователя наружу не
уходит.

## 1. Кандидат и что именно проверено

| Пункт | Результат |
|---|---|
| Провайдер | Open-Meteo, **Air Quality API** (`air-quality-api.open-meteo.com/v1/air-quality`) |
| Модель | **CAMS European Air Quality Forecast**, `models=cams_europe` |
| Регион | Санкт-Петербург поддерживается; запрошенная точка 59.9405, 30.3165 → возвращена ячейка **59.9, 30.3** |
| Виды пыльцы | ровно шесть: `alder_pollen`, `birch_pollen`, `grass_pollen`, `mugwort_pollen`, `ragweed_pollen`, `olive_pollen` |
| Единицы | `grains/m³` для всех шести (проверяется строго, см. §4) |
| Временной шаг | 1 час, ряд строго непрерывный (0 разрывов на 2232 часах) |
| Горизонт прогноза | **до 4 суток**; при `forecast_days=7` последние 20 часов приходят `null` |
| Прошлое | `past_days` до 92; 92 дня пыльцы получены полностью непустыми (2232/2232 на каждый вид) |
| Семантика времени | мгновенное значение на указанный час: `[t, t+1h)` |
| Лицензия | CC-BY-4.0, обязательна атрибуция «data by Open-Meteo.com» и ссылка на CAMS ENSEMBLE |
| Условия free-tier | только некоммерческое использование; < 10 000 запросов/сутки, 5 000/час, 600/минуту |
| Ключи | для free-tier не требуются |

Источник: <https://open-meteo.com/en/docs/air-quality-api>,
условия: <https://open-meteo.com/en/terms>.

## 2. Что показали фактические ответы (а не документация)

### 2.1 Октябрь: значения есть, и они нулевые

Ответ в производственной форме запроса (6 видов, `past_days=1`,
`forecast_days=4`, `timezone=UTC`, `timeformat=unixtime`) — 120 часов,
**все 120 непустые на каждый вид**, но **все значения равны `0.0`**:

```
alder_pollen 0.0   birch_pollen 0.0   grass_pollen 0.0
mugwort_pollen 0.0 ragweed_pollen 0.0 olive_pollen 0.0
```

Это ключевое различие, на котором стоит весь движок: **`0.0` — это
значение, `null` — это пропуск.** Отсутствие данных (за горизонтом) приходит
как `null`; межсезонье приходит как честный ноль модели. Ноль нельзя
выдавать за «измерено, пыльцы нет», а `null` нельзя превращать в ноль.

### 2.2 Сезонный сигнал существует и биологически осмыслен

Отсутствие значения в октябре нельзя истолковать как «источник пуст»:
92 дня прошлого (`past_days=92`) покрывают конец сезона и показывают
реальный сигнал:

| Вид | Часов с ненулевым значением | Максимум, grains/m³ | Когда максимум |
|---|---|---|---|
| `grass_pollen` | 1434 | 32,6 | 2026-07-17 |
| `mugwort_pollen` | 1297 | **348,6** | 2026-08-05 |
| `ragweed_pollen` | 370 | **620,5** | 2026-09-05 |
| `alder_pollen` | 0 | — | — |
| `birch_pollen` | 0 | — | — |
| `olive_pollen` | 0 | — | — |

Порядок и сроки совпадают с календарём пыления Северо-Запада: злаки — июль,
полынь — начало августа, амброзия — конец августа…сентябрь; ольха и берёза
пылят весной (в это окно их нет), маслина в регионе не произрастает. Это
проверка правдоподобия источника, **а не валидация модели**.

### 2.3 Пространственная представительность: ровно одна ячейка

Запрошенная точка притягивается к ближайшему центру ячейки 0,1°:

| Запрошено | Возвращено |
|---|---|
| 59.849, 30.31 | 59.8, 30.3 |
| 59.851, 30.31 | **59.9**, 30.3 |
| 59.949, 30.31 | 59.9, 30.3 |
| 59.951, 30.31 | **60.0**, 30.3 |
| 59.94, 30.249 | 59.9, **30.2** |
| 59.94, 30.251 | 59.9, **30.3** |
| 59.94, 30.351 | 59.9, **30.4** |
| 59.50, 30.31 | 59.5, 30.3 |
| 60.40, 30.31 | 60.4, 30.3 |

Следствия, закреплённые в реализации:

* запрос на центроид пилота описывает **и только описывает** ячейку
  `[59.85, 59.95) × [30.25, 30.35)` — примерно 11,1 × 5,6 км;
* точка вне этой ячейки принадлежит **другому** центру сетки (59.5 → 59.5,
  60.4 → 60.4), значение которой мы не запрашивали. Такие участки остаются
  `unknown` — соседняя ячейка не «занимается взаймы»;
* поэтому сравнение улиц внутри одной ячейки не делается вовсе: у источника
  для этого нет разрешения.

### 2.4 Вне зоны покрытия — честная ошибка

Точка вне домена CAMS Europe (Сингапур 1.35, 103.82; Новосибирск
55.03, 82.92) при `models=cams_europe` возвращает **HTTP 400** и тело
`{"error": true, "reason": "No data is available for this location"}`.
Провайдер превращает это в `PollenUnavailable`, а не в нули.

### 2.5 `cams_global` пыльцу не отдаёт

При `models=cams_global` все 168 запрошенных часов приходят `null`. Это ещё
одна причина фиксировать модель явно (`models=cams_europe`) и проверять
единицы: молчаливый выбор другой модели дал бы ряд из пропусков.

## 4. Что именно проверяет парсер (и почему это часть шлюза)

Молчаливое изменение контракта на стороне провайдера — главный риск таких
интеграций, поэтому парсер отказывает, а не «починяет»:

* `utc_offset_seconds == 0` (запрашиваем UTC) и `hourly_units.time == "unixtime"`;
* единица **каждого** вида ровно `grains/m³`;
* все шесть видов присутствуют и имеют ту же длину, что и ось времени;
* шаг ровно 3600 с, ни одного повтора и ни одного разрыва;
* длина ряда 1…600 часов;
* значение — конечное число в `[0, 100000]`, `bool` значением не считается
  (иначе `true` прошло бы как 1.0);
* возвращённая ячейка не дальше 0,25° от запрошенной точки;
* ответ с `error: true` — отказ.

Отказ означает `pollen_source_invalid` и `unavailable` без чисел.

## 5. Лицензия и условия эксплуатации

* Данные: **CC-BY-4.0**. Атрибуция обязательна и уже входит в контракт ответа
  и в UI: «Pollen data by Open-Meteo.com; CAMS ENSEMBLE (Copernicus
  Atmosphere Monitoring Service) model», лицензия CC-BY-4.0, ссылка на
  документацию API.
* Free-tier — **только некоммерческое** использование: < 10 000 запросов в
  сутки, 5 000 в час, 600 в минуту.
* Расход бюджета: один фиксированный центроид, кэш на 1 час и single-flight
  на процесс. Даже при непрерывной работе это 24 запроса в сутки на процесс,
  то есть доли процента лимита.
* Внешний источник **не включён** ни в одном окружении: нужен явный
  opt-in `POLLEN_SOURCE_ENABLED=true`. Railway и release-конфигурация не
  меняются (см. ограничения этапа).

## 6. Ограничения и открытые вопросы

1. **Нет надёжного признака межсезонья.** Документация говорит, что пыльца
   доступна «в сезон», но API отдаёт вне сезона `0.0`, а не `null` и не
   отдельный статус. Отличить «модель посчитала ноль» от «эмиссий нет» по
   данным нельзя, поэтому отдельный статус сезонной недоступности **не
   вводится**: он был бы выдуманным признаком.
2. **Граница горизонта зависит от прогона модели.** Она приходит как
   `null`-хвост и не имеет фиксированного отступа от «сейчас»; поэтому
   оценка честно становится `partial`, а не «дотягивает» ряд.
3. **Одна ячейка ≠ город.** Значение относится к ячейке ~11 км; для
   прогулки за её пределами оценка не даётся. Расширение на несколько
   фиксированных ячеек — отдельный этап, требующий отдельного обоснования
   (и оно снова внесёт разницу между соседними улицами на границе сетки).
4. **Точность не подтверждена.** Нет наземных наблюдений для сравнения, нет
   калибровки, нет порогов. Всё, что утверждает C7.3, — это концентрации,
   единицы, покрытие и атрибуция источника.

## 7. Вердикт шлюза

| Утверждение | Статус |
|---|---|
| Источник доступен, лицензирован, документирован, воспроизводим | **подтверждено фактическими запросами** |
| Единицы, виды, шаг, горизонт, `null`-семантика проверяемы в коде | **подтверждено тестами** (`test_c7_3_source.py`) |
| Сезонный сигнал правдоподобен | **подтверждено** (92 дня, §2.2) |
| Данные описывают конкретную улицу/двор | **опровергнуто** — одна ячейка ~11 км |
| Концентрации соответствуют реальности количественно | **не проверено**, `MODEL_VALIDATED` не присвоен |
| Данные пригодны для медицинских выводов | **опровергнуто** — порогов и категорий нет и не вводится |

Запасной вариант, который **не использовался**: если бы шлюз не подтвердил
пригодность, движок и UI были бы реализованы и протестированы на
синтетических фикстурах, а production честно возвращал бы `unavailable`.
Именно так работает поведение по умолчанию (`POLLEN_SOURCE_ENABLED=false` →
`pollen_not_configured`), но по причине opt-in, а не по причине отсутствия
источника.
