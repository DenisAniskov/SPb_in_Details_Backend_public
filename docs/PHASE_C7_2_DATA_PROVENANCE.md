# C7.2 — Происхождение данных, лицензии и воспроизводимость

Всё, что движок C7.2 использует как «реальность», зафиксировано по хэшам и
воспроизводится офлайн из артефактов в репозитории. Синтетические данные в
production-пути не используются нигде.

### Что в снимке есть (по coverage audit)

Аудит (`docs/phase_c7_2_acquisition/coverage_audit.json`) считает длину,
обрезанную по bbox — **это длина way'ев, а не уникального покрытия сети и не
покрытие маршрутов**:

* 1094 way с тегом `highway` (все типы), 42 144 м;
* пешеходные типы (`footway`, `pedestrian`, `path`, `steps`, `corridor`,
  `living_street`): **535 way, 24 290 м**;
* `surface` присутствует на 22 405 м из 24 290 м (≈92 %); **1885 м вообще без
  тега покрытия**;
* `smoothness` присутствует лишь на 4586 м (≈19 %);
* `covered=yes`: 12 way / 92 м; `tunnel=building_passage`: 32 way / 344 м.

### Чего в снимке НЕТ

Ни `surface`, ни `smoothness` не описывают дренаж, уклон, глубину неровностей,
влажность грунта или работу ливневой канализации. Отсутствие тега — это
отсутствие данных, и движок обращается с ним именно так (класс покрытия =
«неизвестно», метры `unknown`, причина `surface_unknown`). Наличие way в
пилоте не подтверждает, что линия MapKit проложена именно по нему: подтверждение
даёт только совпадение геометрии по правилам §3 `PHASE_C7_2_MODEL.md`.

### Воспроизводимость (офлайн, без сети)

```bash
cd backend
python -m scripts.acquire_phase_c7_2_osm --verify      # хэши исходника
python -m scripts.build_phase_c7_2_ways --check-reproducible   # байтовая сборка датасета и аудита
python -m pytest tests/test_c7_2_dataset.py -q         # независимая проверка в CI-наборе
```

`test_real_pilot_is_byte_reproducible_and_checksum_pinned` пересобирает
датасет дважды из пиннутого исходника и сравнивает байты; подмена любого
хэша падает с `payload checksum mismatch`, не подменяя данные. Записи о
попытках acquisition (включая таймаут Overpass в 12:35:41Z, после которого
использован официальный OSM API) лежат в `manifest.json` и
`failed_attempts.json`.

## 2. Погода: модельные осадки Open-Meteo

| Свойство | Значение |
|---|---|
| Поставщик | Open-Meteo, `https://api.open-meteo.com/v1/forecast` |
| Модель | DWD ICON (`models=icon_global`), сетка 0.1°, номинал ~11 км |
| Шаг | 1 час, семантика бина `(t−1ч, t]`, UTC (`timeformat=unixtime`, `timezone=UTC`) |
| Поля | `precipitation`, `temperature_2m`, `snowfall` |
| Лицензия | **CC-BY-4.0**; free-tier — **только некоммерческое использование** |
| Атрибуция | «Weather data by Open-Meteo.com; DWD ICON model» |
| Проб-свидетельство | `docs/phase_c7_2_acquisition/weather_public_pilot.json`, raw_sha256 `82ced8080552d7a8b5cfb8210b150f7ced33fc2cca68b8e5e78a0855b93c1607`, 96 часов, 2026-10-14T00:00Z–2026-10-17T23:00Z, один ручной probe 2026-10-16T12:36:24Z |

Ключевые честные пометки (и в метаданных, и в рантайме):

* это **модельные** данные (прогноз + недавний архивный прогноз), а не
  наблюдения: `observed_at = null`, `model_issued_at = null`;
* проб зафиксирован как `not_a_runtime_weather_cache: true` — он не является
  кэшем приложения и не подставляется, если провайдер не работает;
* рантайм-провайдер включается **только** явным `PUDDLE_WEATHER_ENABLED=true`
  после принятия оператором условий free-tier; до этого endpoint отвечает
  `weather_not_configured` (честная недоступность, не «сухо»);
* наружу уходит **одна фиксированная точка** пилота (`latitude/longitude`
  конфигурации), никогда — маршрут или пользовательские координаты;
* серия кэшируется на 15 минут, один запрос на окно (single-flight);
  ответ ограничен 128 КиБ, тайм-аут 3.5 с + общий 4 с.

Проверка проб без сети: `python -m scripts.probe_phase_c7_2_weather --verify`.

## 3. Прочие входы

* **Геометрия и длительности прогулки** — native MapKit SDK 4.45.0 на
  устройстве; сервер не пересчитывает маршрут и не делает routing-запросов.
* **Часовой пояс** — из `departure_at`; наивное время отклоняется (422).
* **Время симулятора** (C4.1) — единственный источник модельного времени в
  симуляторе; устройство не смешивает его с настенным временем.

## 4. Лицензионные обязанности в продукте

* Отображение «© OpenStreetMap contributors» + ODbL-1.0 и «Open-Meteo /
  DWD ICON» + CC-BY-4.0 в карточке оценки (передаются в полях
  `dataset_provenance` и `weather_provenance`).
* Никакой переупаковки OSM-данных как собственного датасета; внутренний
  JSON — производная база, распространяемая под ODbL.
* Модельные погодные значения не перепродаются и не выдаются за наблюдения.
