# Phase C7.3 — Архитектура

C7.3 добавляет **одну независимую read-only оценку**: концентрации пыльцы
вдоль уже существующей прогулки. Оценка не участвует в выборе маршрута, не
влияет на Shade/Scenic/Puddle и не меняет ни одного коэффициента предыдущих
этапов.

## 1. Компоненты

### Backend (новое)

```
app/services/pollen_engine/
  source.py    # внешний источник: Open-Meteo Air Quality / CAMS Europe
  model.py     # арифметика экспозиции: [t, t+1h), интеграл, покрытие
  engine.py    # оркестрация: окна времени, ячейка, статусы, причины
  wiring.py    # composition root: singleton-провайдер + явный opt-in
app/schemas/pollen.py                 # отдельные схемы C7.3
app/api/v1/endpoints/pollen.py        # POST /environment/pollen/analyze
scripts/probe_phase_c7_3_pollen.py    # шлюз источника (offline --verify)
```

Разделение обязанностей то же, что в C7.2, и намеренно буквальное:

| Слой | Знает | Не знает |
|---|---|---|
| `source.py` | HTTP, единицы, время, `null`, кэш, single-flight | геометрию маршрута, статусы оценки |
| `model.py` | как интегрировать мгновенные значения по окнам | откуда взялся ряд, что такое «этап» |
| `engine.py` | этапы, POI-сдвиги, ячейку, статусы и причины | HTTP, как устроен ответ API |
| `endpoints/pollen.py` | валидацию запроса, тайм-ауты, округление, атрибуцию | как считается экспозиция |

### Frontend (новое)

```
frontend/lib/data/models/pollen_analysis_model.dart   # строгая модель + причины
frontend/lib/services/pollen_analysis_service.dart    # общий ApiClient, типизированные отказы
frontend/lib/providers/pollen_assessment_provider.dart# инвалидация, in-flight, remaining path
frontend/lib/ui/widgets/pollen_assessment_section.dart# карточка «Пыльцевая нагрузка»
```

Изменено ровно в точках подключения: `api_constants.dart` (эндпоинт и
единица), `main.dart` (DI), `route_details_sheet.dart` и
`live_navigation_sheet.dart` (монтирование карточки). Никакой второй
HTTP-конфигурации не создаётся.

## 3. Точки, где архитектура сознательно повторяет C7.2 (и почему)

1. **Долгоживущий провайдер.** `wiring._cached_pollen_provider` —
   `lru_cache` по (enabled, lat, lon), а `_build_pollen_provider` вынесен как
   точка подстановки транспорта в тестах. Это прямое следствие дефекта
   C7.2, найденного на ревью: провайдер, создаваемый на каждый запрос, несёт
   кэш и single-flight ровно одного запроса. Здесь это закрыто **до** ревью и
   проверено интеграционным тестом через production wiring.
2. **Явный opt-in.** `POLLEN_SOURCE_ENABLED=false` по умолчанию: внешний
   источник с некоммерческой лицензией не включается «сам». Поведение по
   умолчанию — честное `pollen_not_configured`, а не архивные значения.
3. **Инвалидация и in-flight.** Провайдер сравнивает идентичность плана и
   сессии, lock, признак перестроения и модельное время; счётчик `_request`
   отбрасывает ответ, пришедший после инвалидации.
4. **Remaining path.** Во время прогулки оценка строится на
   `buildRemainingRoute()` — валидированном обрезании из C7.1.2, — а не на
   полном исходном маршруте.

## 4. Что C7.3 не делает по построению

* **Не маршрутизирует.** Ноль обращений к native routing, ноль изменений
  геометрии, манёвров, порядка POI и planning lock. Это проверяется
  Flutter-тестами на живом `NavigationProvider`.
* **Не объединяет факторы.** Пыльца не входит ни в Shade, ни в Scenic, ни в
  Puddle scoring и не суммируется с ними: у неё отдельные схемы, отдельный
  сервис и отдельная карточка. Сопоставимость данных не подтверждена, а без
  неё объединение было бы вымыслом.
* **Не претендует на улицу.** Один фиксированный центроид = одна ячейка
  ~11 км; участки вне неё остаются `unknown`.
* **Не отдаёт медицинских выводов.** Ни порогов, ни уровней, ни
  рекомендаций — только концентрации, единицы, покрытие и атрибуция.

## 5. Конфигурация и нагрузка

| Механизм | Значение |
|---|---|
| Внешний запрос | 1 фиксированный центроид, `models=cams_europe`, 6 видов, `past_days=1`, `forecast_days=4` |
| Кэш | 1 час на процесс (пыльца меняется медленно; ряд часовой) |
| Single-flight | `asyncio.Lock` с двойной проверкой |
| Тайм-ауты | httpx 6 с внутри `asyncio.timeout(8)`; эндпоинт 10 с сверху и 10 с на анализ |
| Лимит ответа | 256 КиБ, обрыв по потоку до парсинга |
| Конкурентность | семафор на 2 одновременных анализа |
| Бюджет free-tier | доли процента (24 запроса/сутки на процесс против 10 000) |

## 6. Соответствие ТЗ §2 (сохранение текущей модели)

Yandex MapKit Full SDK остаётся единственным источником реальных пешеходных
маршрутов, геометрии, длительностей и манёвров. C7.3 читает **готовые**
`legs` и их native-длительности, не подменяет их, не пересчитывает и не
предлагает альтернатив. Все проверки, которые требует §2, выполняются
неизменёнными механизмами C7.1/C7.2: ограничения размера геометрии,
защита от in-flight ответов и правила planning lock.
