# Развёртывание

Документ описывает **самостоятельное** развёртывание этого backend'а. Настройки
собственного рабочего окружения проекта и его базы данных здесь не публикуются и
не должны копироваться: публичный исходный код не даёт доступа к рабочей службе.

## Что требуется

* Python 3.14.x (или официальный образ Python 3.14 для контейнера) и SQLite.
* Один процесс и один worker (`WORKERS=1`): каталог и журнал квот — один писатель.
* Записываемый постоянный каталог под файл базы (в контейнере — том `/data`).
* Модельные датасеты в `data/` — неизменяемые, только чтение.
* Обратный прокси с HTTPS, если сервис доступен не только локально.

## Локальный запуск

```bash
python -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
.venv/bin/python run.py
```

`run.py` отключает access-log (URL и координаты не пишутся), включает
доверенный прокси только при заданном `TRUSTED_PROXY_IPS`, ограничивает
конкурентность (`SERVER_CONCURRENCY_LIMIT`) и завершает работу за 15 секунд.
Каталог создаётся и синхронизируется при первом старте; повторные старты
идемпотентны по `catalog_key`.

## Контейнер

```bash
docker build --platform linux/amd64 -t smartnavigator-backend:local .
docker compose up -d --build
python scripts/container_smoke.py --image smartnavigator-backend:local
```

Свойства образа и `compose.yaml`:

* Зависимости ставятся из `requirements.runtime.lock` с `--require-hashes
  --only-binary=:all:`; базовый образ закреплён по digest.
* Процесс работает от UID/GID **10001**, файлы приложения — только чтение
  (`chmod -R a=rX /app`), `HEALTHCHECK` опрашивает `/ready`, останов — `SIGTERM`.
* В `compose.yaml` корневая файловая система read-only, `/tmp` — `tmpfs` без
  выполнения, `cap_drop: ALL`, `no-new-privileges`, окно остановки 20 секунд,
  порт публикуется только на `127.0.0.1` (TLS добавляет прокси).
* В образ копируется ровно необходимое: приложение, `run.py`, entrypoint,
  скрипт резервного копирования и три ODbL-датасета — по allowlist в
  `.dockerignore`, без `.env`, баз и тестов.

**Bootstrap тома.** Если платформа монтирует том от имени root и передаёт
контейнеру root, entrypoint выполняет узкую операцию: меняет владельца
**только** самого каталога `/data` на 10001 и сразу сбрасывает привилегии. Он
делает это лишь тогда, когда сама платформа явно сообщает о таком томе
(`RAILWAY_VOLUME_MOUNT_PATH=/data`) и `DATABASE_URL` оставлен равным
`sqlite+aiosqlite:////data/smart_navigator_spb.db`; в любом другом случае старт
отклоняется с понятным сообщением, а существующие SQLite-файлы чужого владельца
не «починяются» автоматически. В Docker Compose этот путь не нужен:
именованный том наследует владельца 10001, и контейнер стартует сразу
непривилегированным.

## Обновление датасетов

Датасеты read-only и лежат внутри образа. Чтобы обновить покрытие без
пересборки, смонтируйте новый файл поверх пути по умолчанию:

```bash
docker run --rm -v "$PWD/new_shade.sqlite:/app/data/shade_buildings_spb_pilot.sqlite:ro" ...
```

Для Quiet Engine целостность проверяется по SHA-256-манифесту, поэтому новый
gzip без соответствующего манифеста не будет использован.

## Резервные копии

```bash
python scripts/sqlite_backup.py --output backups/backup.db      # онлайн-копия
python scripts/sqlite_backup.py --verify-only backups/backup.db # проверка в изолированном каталоге
```

Скрипт использует стандартную библиотеку и онлайн-API SQLite: исходная база
открывается только на чтение, в копию попадают зафиксированные страницы WAL, а
успех подтверждается восстановлением в одноразовом каталоге. Работающая база
никогда не восстанавливается автоматически и не перезаписывается.

Восстановление выполняет оператор: остановить сервис, заменить файл базы (и
удалить устаревшие `-wal`/`-shm`), запустить сервис и проверить `/ready`.
Для схемных миграций C13 предусмотрен флаг `AI_ASSISTANT_BACKUP_ON_START`,
который делает проверенную копию **до** изменений схемы и прерывает старт при
её неудаче.

## Проверки после развёртывания

| Проверка | Как |
| --- | --- |
| Процесс | `GET /health` → `{"status": "ok"}` |
| Готовность базы | `GET /ready` → `{"status": "ready"}` |
| Каталог | `GET /api/v1/places?limit=1` возвращает запись |
| Контейнер целиком | `python scripts/container_smoke.py --image <image>` |
| Права | контейнер не работает от root, `/data` принадлежит 10001 |
| Завершение | останов контейнера завершает процесс без OOM и без потери базы |

`/docs` публикуется только при `BACKEND_ENV=development`; в `staging` и
`production` схема закрыта.

## Границы

* Только один экземпляр сервиса: горизонтальное масштабирование на SQLite не
  поддерживается.
* TLS/HTTP-прокси, ограничение по адресам и внешний WAF — ответственность
  оператора; сервис их не заменяет.
* Публичный репозиторий не содержит ни ключей, ни параметров рабочего
  окружения проекта: их нужно создать заново (см. [CONFIGURATION.md](CONFIGURATION.md)).
